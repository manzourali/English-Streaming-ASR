# Experiments

An experiment is defined by YAML, a seed, dataset/model identifiers, and an output root. Phase 1 times model loading separately from per-utterance streaming processing using `time.perf_counter()`. WER lowercases text, removes punctuation other than apostrophes, and collapses whitespace; raw and normalized reference/prediction text are saved. RTF is wall-clock processing time divided by audio duration, under the tested hardware/software/chunk configuration. Run directories contain resolved config, metadata, logs, JSONL predictions, JSON metrics, and a Markdown report. No value is populated unless measured.

Phase 2 additionally records VAD frame size, aggressiveness, decision timing, and VAD RTF separately from ASR RTF. The current primary design forwards continuous audio to ASR, so VAD is observed rather than used to discard samples. Frame-level VAD accuracy remains unmeasured unless valid frame-level references are available.

Phase 3 reports dataset properties only: mixture count, duration, overlap duration/ratio, regime distribution, speaker distribution, gain distribution, validation errors, and generation outputs. It does not report ASR WER. Generation is seeded with NumPy and generated data remains outside Git.

Phase 4 records condition, source references, overlap metadata, hypothesis, incremental hypotheses, RTF, first-output latency, finalization latency, and chunk timing. WER is corpus-level for valid non-overlap controls only; overlap WER is explicitly not measured for the single-stream output format.

Phase 5 evaluates the selected streaming OSD candidate one fixed frame at a time. Reference and prediction intervals are aligned by reference-frame midpoint, making unequal frame durations explicit. The primary metrics are binary overlap precision, recall, and F1 plus the full three-class confusion matrix. Overlap event latency is the first predicted overlap start minus the true event start; it is left signed rather than clipped. Processing cost is reported as OSD RTF, and all metrics remain `NOT_MEASURED`/`null` where the split contains no applicable events.

Phase 6 runs a deliberately small matrix: always-normal control, adaptive oracle routing, and adaptive predicted-OSD routing. The latter two use identical controller settings unless the configuration explicitly changes them. Oracle timing is reported as `ORACLE ROUTING — NOT A DEPLOYABLE SYSTEM`. The shared-WhisperRT overlap control does not provide a different ASR capability, so Phase 6 reports routing precision/recall/F1, routing confusion, transition count, detection-to-routing delay, route durations, controller errors, and total RTF; it does not claim a WER improvement. Routing traces record the source-timing label, selected route/state, confidence, timestamp, and errors for each chunk. WER remains available only under the Phase 4 validity rules.

Phase 7 defines the multi-talker condition through stream/channel permutation-invariant WER. It pads unequal stream counts with empty references/hypotheses so missed or spurious channels are not ignored, then chooses the minimum-error output-channel permutation. This is not speaker-attributed WER: channel IDs are not person identities. `run_multitalker.py` records structured streams, first output when measurable, RTF, and the exact configured external decoder condition. Metrics remain `NOT MEASURED` until an exact SURT decoder/checkpoint and Phase 3 manifest are executed.

Phase 8 protects the test set by loading it solely for split-leakage checks; training batches come only from the configured train split and validation batches only from the validation split. The planned first matrix is base, clean, overlap, and mixed, but no condition has executed here. A real run must report the exact external recipe revision, checkpoint, parameters, hardware, training history, best/last checkpoints, clean/overlap metrics, streaming behavior, and adaptive behavior. OSD thresholds remain validation-only parameters.

Phase 9 fixes the comparison protocol: paired improvements require exactly matching sample IDs, metric, and optimization direction; lower-is-better metrics such as WER report positive improvement only when the candidate is lower. Per-example error/reference counts permit weighted corpus aggregation, while bootstrap confidence intervals are generated deterministically from recorded examples. Oracle rows are labelled non-deployable and excluded from the primary table. No real Phase 9 record set exists in this checkout.
